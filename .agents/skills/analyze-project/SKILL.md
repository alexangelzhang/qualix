# 项目架构分析

对当前项目进行一次结构化的架构分析，输出简洁可复用的摘要。目标是让后续会话不需要重新扫描代码库。

## 执行步骤

### 1. 读取已有上下文
- 检查项目根目录是否有 `CLAUDE.md`、`README.md`、`ROADMAP.md`、`AGENTS.md`
- 如果 `CLAUDE.md` 中已有 `## Architecture` 或 `## 架构` 章节，先读取现有内容，后续只做增量更新

### 2. 识别项目基本信息
- 项目名称和类型（库/服务/CLI/框架）
- 主要语言和框架（从 package.json / pyproject.toml / pom.xml / build.gradle 等推断）
- 入口点（main.py / cli.py / app.py / index.ts / Application.java 等）

### 3. 映射模块结构
- 列出顶层目录及其职责（一句话说明每个目录干什么）
- 识别核心模块之间的依赖关系（谁调用谁）
- 标记外部依赖中的关键组件（数据库、消息队列、第三方 API 等）

### 4. 识别关键设计模式
- 路由/调度模式（如果有）
- 配置管理方式
- 测试组织方式和覆盖情况
- 错误处理和日志模式

### 5. 输出摘要
将分析结果写入 `CLAUDE.md` 的 `## Architecture` 章节（如果文件不存在则创建），格式如下：

```markdown
## Architecture

**项目类型**：[库/服务/CLI/框架]
**主要语言**：[语言 + 框架]
**入口点**：[文件路径]

### 模块结构
| 目录 | 职责 | 关键文件 |
| --- | --- | --- |
| src/xxx | 一句话说明 | 关键文件列表 |

### 核心依赖关系
- A → B：说明调用关系
- B → C：说明调用关系

### 设计模式
- **路由**：简述
- **配置**：简述
- **测试**：简述（覆盖率如果能获取的话）

### 外部依赖
- 数据库：xxx
- 消息队列：xxx
- 第三方 API：xxx

*最后更新：[日期]*
```

## 约束
- 不要启动子 agent 或 memory observer
- 不要修改项目源代码，只更新 CLAUDE.md
- 摘要控制在 50 行以内，追求简洁可扫描
- 如果项目很大，聚焦核心模块，长尾模块一句话带过
- 如果已有架构摘要，只更新变化的部分，不要全部重写
