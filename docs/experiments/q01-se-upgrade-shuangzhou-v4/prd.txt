# 一、需求背景/目标
## 需求背景
- 25年H1售后满意度调研显示，售后NSS得分达到76.05%，预计26H1达到目标80%
- 调研反馈显示，授权店提前交车、移动工单数据加密、索赔单增加筛选项、容量配置提醒、到店工单筛选增加字段、到店工单列表展示优化，导致售后体验效果差、效率低，需高优补齐。
## 需求目标
- 项目总体目标：提升NSS分数
- 本次双周迭代4.0目标：优化售后体验，提高售后服务效率

### 零售通-授权店提前交车
- 背景：授权门店为车主提供"预约送车"服务时，目前“待交车"状态可操作。在事故维修场景下，由于保险定损周期较长会出现车辆已修完，但因未定损导致无法交车情况，导致用户体验受损和门店运营成本提升目前门店提前交车方案：
- 开具0元工单使用取送车服务，影响商政数据计算
- 门店自费呼叫代驾送车，增加门店运营成本，且不消耗权益会提高服务包成本
- 工单状态机
- 提前交车状态流转
模块
原型图
功能说明
- 授权店
- 到店工单-工单详情
- 工单详情增加「申请提前交车」按钮
- 展示条件：
  - 工单状态：待申请结算、待申请结算（审批中）、待支付、部分支付
  - 工单条件：付费类型是保修或者有取送车权益
  - 角色：店长、服务顾问主管、服务顾问
- 点击「申请提前交车」按钮，弹出侧边抽屉，填写申请说明
- 标题：提前交车申请
- 文案：提示：工单未结算前提前交车，需要提交申请，请谨慎斟酌提前交车风险
- 小标题：*申请理由
- 输入框：限制500字，文案提示“请输入提前交车理由”
- 申请理由不能为空，若为空提示toast“申请理由不能为空”，且无法提交
- 当提前交车申请审批中时，展示「申请提前交车」按钮，提交申请原因后报错toast“提前交车申请审批中，请勿重复提交”
- 若提前交车申请审批通过，不展示「申请提前交车」按钮
- 申请理由点击提交后触发审批
- 审批流：服务顾问/服务顾问主管/店长➡️授权店店长/财务
  - 审批角色为或的关系，即该店的授权店长或授权店财务一人审批即可
- 审批通过后展示「预约代驾还车」按钮
- 审批页相关功能见下一模块说明
- 待交车状态前代驾单服务完成，文案为已交车+已提前交车+时间
- 工单服务完成后保留“已交车+已提前交车+时间”
- 若在待交车状态前，代驾单已服务完成
- 此时【工单卡片】展示文案「已交车」
  - 若状态为待申请结算（审批中）状态，后面增加「已交车」
- 待交车状态下，工单流转状态不变
- 举例：若该工单用户自费已支付+代驾单服务完成，则工单状态从【待交车】流转为已交车
- 待交车下方保留「已提前交车」及代驾单服务完成时间
- 授权店
- 我的-审批-我发起的
- 申请人在「我发起的」tab：查看申请详情，同时可以撤销申请
- 展示内容如下
- 审批信息
  - 审批类型：授权店提前交车
- 车辆信息
  - VIN：MOCKN1000000282742
- 工单信息
  - 工单号、工单创建时间、门店名称
- 申请原因
- 交互：点击撤销申请，该审批被撤销
- 已拒绝审批单，上发展示拒绝原因
- 审批流：服务顾问/服务顾问主管/店长提交➡️授权店店长/财务审批
- 只有一层审批，审批角色为或的关系，即该店的授权店长或授权店财务一人审批即可
- 授权店
- 我的-审批-待审批
- 审批人在「待审批」tab查看审批信息
- 展示内容如下
- 审批信息
  - 审批类型：授权店提前交车
- 车辆信息
  - VIN：MOCKN1000000282742
- 工单信息
  - 工单号、工单创建时间、门店名称
- 申请原因
- 交互：
- 点击【通过】，弹出审批弹窗，点击确认该审批单被通过
- 点击【拒绝】，弹出侧边抽屉，填写拒绝原因；点击提交后即驳回该申请
- 审批通过的单子移至【已审批】
### 零售通-移动工单数据加密
模块
原型图
功能说明
- 移动工单-工单卡片（服务完成工单）
- 字段隐藏标准
- 姓名:
  - 半隐藏:郝**,隐藏第一个字之后的内容
    - **跟名字的长度
- 手机号:
  - 半隐藏:131****5678,隐藏第4~7位
- 地址:
  - 半隐藏:北京市-海淀区*****,只露出省市;(直辖市只露出市区,数据结构上,直辖市的市=省)
- VIN:
  - 半隐藏:*****00194630,只露出后8位
- 已完成的移动工单，卡片上VIN、用户姓名、手机号、地址，按照上述规范隐藏
- 卡片上不支持隐藏与显示的交互,只隐藏
- 未完成的工单,保持现状
