## 二、需求清单

### REQ-001 物流取旧送新能力识别与标记（P0）
**来源**: prd.md:110-172

基于"品类 + SKU + 收货地址"三段式校验，综合判定工单是否支持物流取旧送新，识别通过后打标展示给网点和工程师。

- **触发时机**：换货建单、检测改换货意向变更
- **识别流程**：品类白名单校验 → SKU黑名单剔除 → 调用履约中心 isSendAndInstallSupported 接口
- **展示效果**：工单详情顶部【物流取旧】标签；工程师弹窗提示；服务通列表【送新取旧】标签

### REQ-002 工单流变更（P0）
**来源**: prd.md:174

强安装品类（洗衣机）命中物流取旧送新标识时，换货工单直接走非强安装工单流，不触发二次上门换新流程。

### REQ-003 换货流程适配（P0）
**来源**: prd.md:175

- 待上门→待服务时第二次能力识别
- 仅允许选择「上门换新仅检测」处理方法
- 工单提交需双重门控（标识支持 + 处理方法匹配）
- 有物流取旧送新标签时忽略入库单生成

### REQ-004 检测单信息传递给物流（P0）
**来源**: prd.md:176

完单后向物流侧传递：工单号、原订单号、商品SN、处理方式、工程师姓名/电话、网点名称、检测结果、工单照片（FAULT+PROCESSED类型）、特批单号等，触发生成「送新单」+「取旧单」。

### REQ-005 物流单关联取旧信息XMS展示（P0）
**来源**: prd.md:177

工单详情物流功能区同时展示取旧单和换新单信息及物流轨迹。

### REQ-006 换货完成工单闭环（P0）
**来源**: prd.md:178

对接物流妥投消息，驱动工单状态：换货中 → 已换货完成 → 已妥投完成。

### REQ-007 换货取消逆向闭环（P0）
**来源**: prd.md:179

- 网点取消时同步通知物流下游取消
- 物流推送取消消息时：不回退工单节点、仍对网点结算、新增「物流原因取消」日志、终态服务完成
- 物流原因取消工单的SN允许继续建售后工单（建单检验需适配）

### REQ-008 拒收换处理（P0）
**来源**: prd.md:180

换新单货物破损用户拒收时，OC生成第二张换新单，售后执行换绑。

## 五、GAP 清单

### GAP-001（HIGH）
**问题**：上线时间配置项 `logistic_exchange_enable_time` 的初始值和切量方式 PRD 未描述。  
**影响**：配置项为空时，所有工单默认不支持物流取旧送新，上线后功能无法启用。  
**需要**：产品/运营确认上线时配置的初始值。

### GAP-002（MEDIUM）
**问题**：PRD 字段清单（故障描述、受理备注、故障现象、三包起始日期等）在代码的 `buildLogisticExchangeExtInfo` 中未见明确映射。  
**影响**：可能导致物流侧取旧人员缺少关键检测信息。  
**需要**：研发确认字段完整性对应关系。

## 六、OPEN 清单

### OPEN-001
**问题**：拒收换后售后换绑的具体操作步骤 PRD 未详述（原工单换绑 vs 新建工单）。  
**决策方**：产品（孙赫阳/郝宇楠）

### OPEN-002
**问题**：物流原因取消后 SN 允许再次建单，建单检验适配规则未说明（完全豁免 vs 条件豁免）。  
**决策方**：技术（研发负责人）

### OPEN-003
**问题**：「上门换新仅检测」处理方法劳务费配置（26-30元），是否影响现有费用结算逻辑，需确认是否有特殊规则。  
**决策方**：产品（功能清单涉及结费评论）
