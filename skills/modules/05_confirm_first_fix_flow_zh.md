# 模块 05：Confirm-First 修复流（人工确认优先）

## 目标

确保“先确认、再修改”，杜绝自动修复。

## 步骤

1. 汇总问题并排序：
   - 先 Critical，后 Informational。
2. 批量向用户发起确认：
   - 每项提供三选一：
     - A) 按建议修复
     - B) 暂不修复
     - C) 按用户指定方案修复
3. 未获得明确选项前：
   - 不执行任何代码改动。
4. 获批后执行修改：
   - 仅修改 A/C 选中的项。
   - 每项输出“修改内容 + 涉及文件 + 影响说明”。
5. 未处理项沉淀：
   - 进入“已知风险”列表。

## AskUserQuestion 输出模板

```text
我发现 N 个问题，按严重级排序如下。

1. [CRITICAL] <file:line> <问题摘要>
   建议: <修复建议>
   请选择: A 修复 / B 跳过 / C 自定义修复

2. [INFO] <file:line> <问题摘要>
   建议: <修复建议>
   请选择: A 修复 / B 跳过 / C 自定义修复

RECOMMENDATION: 优先修复全部 Critical。
```
