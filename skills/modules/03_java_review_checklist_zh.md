# 模块 03：Java 评审清单（DDD + TMF + 防漏）

## 目标

按严重级别对 Java 代码做两阶段评审，并给出可执行建议。

## Critical（必须优先）

1. 需求语义与实现一致性
   - `REQ/BR/SEM` 是否能在代码中找到对应实现证据。
   - 是否存在“需求明示规则未落地”（如排序键、状态守卫、窗口边界）。
2. DDD/TMF 分层职责
   - Application 是否承载了 Domain 规则（违规）。
   - TMF Step 是否通过 `TMF.findAbility()` 调用能力，是否出现直接注入 Ability。
   - Ability 是否继承 `AbstractDomainAbility<Model, Extension>`。
3. SQL 与数据安全
   - SQL 是否参数化。
   - MyBatis/JPA 是否存在拼接注入风险。
4. 事务边界
   - `@Transactional` 边界是否覆盖关键写路径。
   - 异常回滚语义是否正确。
5. 并发安全
   - 并发写是否具备幂等或乐观锁/版本控制。
   - 共享状态是否线程安全。
6. 信任边界
   - 外部输入（请求体、消息、模型输出）是否做 schema/字段校验。
7. 枚举与状态完整性
   - 新增枚举值是否覆盖 `switch/if` 所有分支。

## Informational（重要但可排期）

1. 条件副作用
   - 同条件下是否有重复或遗漏副作用。
2. 魔法值与字符串耦合
   - 硬编码值是否应抽常量。
3. 异常一致性
   - 错误码、日志、异常映射是否一致。
4. 测试缺口
   - 新逻辑是否缺单测/集成测试。
   - 高风险分支是否缺异常单测（EUT）。
5. 文档陈旧
   - 关键行为变更是否未更新 README/设计文档。
