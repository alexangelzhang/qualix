# 资金安全治理控制项

本文件用于判断系统是否具备“即使出错也能被及时发现和止损”的能力。

## 一、事前防控

重点控制项：
- 参数边界校验：负数、零值、超大值、币种、精度
- 权限与审批：角色、资源归属、审批链、金额上限、双人复核
- 准入规则：状态校验、业务条件校验、额度校验、频率限制
- 幂等与防重：业务唯一键、唯一索引、消费记录、补偿记录
- 并发控制：条件更新、事务、锁、版本号
- 信任边界：验签、来源校验、租户隔离、订单归属校验

判定问题：
- 是否依赖单一手段防重
- 是否只有应用层校验，没有数据库兜底
- 是否有高风险后台操作但缺少审批和审计

## 二、事中监控

重点控制项：
- 金额异常监控：单笔、单日、异常峰值、异常频次
- 状态异常监控：重复成功、非法迁移、补偿高频触发
- 一致性监控：渠道成功本地失败、总账分账差异
- 链路追踪：traceId、业务单号、请求来源、调用链
- 告警机制：分级、收敛、升级、值班响应

判定问题：
- 能否在分钟级发现错误重复出款或超额退款
- 是否有明确的 P0 / P1 告警策略
- 是否有上下文足够完整的审计日志

## 三、事后处置

重点控制项：
- 对账：实时、准实时、T+1，是否覆盖关键链路
- 差异分类：少记、多记、重复记、状态不一致、渠道不一致
- 止损：冻结、熔断、暂停补偿、关闭高风险入口
- 修复：修复脚本、dry-run、回滚、操作留痕
- 复盘：根因、影响范围、监控补齐、控制加固

判定问题：
- 差异能否自动发现，还是只能靠人工投诉
- 是否能快速暂停某类高风险出金动作
- 修复操作是否可追溯

## 四、最小治理基线

以下能力缺失时，应显著提高风险评级：
- 没有对账
- 没有异常金额告警
- 没有审计日志
- 没有止损开关或熔断
- 没有修复工具
- 没有消费/补偿幂等记录

## 五、治理建议输出方式

治理建议不要只写“补监控、补对账”。

应明确：
- 目标：防什么损失
- 触发条件：什么情况下触发告警/冻结/熔断
- 覆盖范围：哪些业务单、哪些系统、哪些状态
- 验证方式：如何确认治理已生效

示例：
- 增加“同一业务单 10 分钟内重复成功超过 1 次”的 P0 告警
- 建立“退款单累计金额 > 实付金额”的准实时对账校验
- 为后台补偿接口增加审批单号和双人复核要求
- 为修复脚本增加 dry-run、影响条数预估和审计日志
