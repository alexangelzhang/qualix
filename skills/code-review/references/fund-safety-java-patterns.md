# Java 资损风险模式库

第一版重点覆盖 Java/Spring 生态常见实现。

## Spring 事务边界

高风险模式：
- 资金主流程不在事务内
- 同类方法内部调用导致 `@Transactional` 不生效
- 事务内发 MQ/调下游，但没有事务消息或补偿闭环
- 事务提交前后副作用顺序错误

重点问题：
- 本地落账失败但下游成功怎么办
- 事务回滚后消息是否已发出
- 是否把“查询 + 判断 + 更新”拆到了事务外

## MyBatis / JPA 原子更新

危险模式：
- 先 `select` 再 `update`
- 累计退款金额用两次 SQL 完成
- 余额扣减不带条件
- 缺失版本号或 `where amount >= ?` 这类保护条件

优先建议：
- 条件更新
- 乐观锁版本号
- 唯一索引兜底
- 必要时 `select for update`

## BigDecimal 与金额处理

危险模式：
- `new BigDecimal(0.1)`
- 使用 `equals` 比较金额大小
- 未统一舍入模式
- 元和分在不同方法中来回转换
- 手续费、折扣、税费未校验最小值和最大值

优先检查：
- 构造方式是否来自字符串或整数分值
- 金额比较是否用 `compareTo`
- 汇总金额是否在同一精度和币种下完成

## MQ 消费与重复处理

高风险模式：
- 消费者先执行业务，再写消费记录
- 只用消息 ID 去重，但业务侧可能重发不同消息 ID
- 消费失败后重试逻辑没有幂等
- 消费记录没有唯一索引

重点场景：
- 支付回调通知
- 退款结果通知
- 结算结果落账
- 券/积分发放
- 批处理补偿消息

## Redis 锁与分布式锁

危险模式：
- 只加锁不落库
- 锁范围过大或过小
- 锁过期时间覆盖不了业务执行时间
- 解锁未校验 owner
- 认为“加了锁就等于幂等”

结论规则：
- 锁只能降低并发竞争，不能替代唯一索引和幂等记录

## 定时任务与补偿任务

高风险模式：
- 按状态扫描失败记录并无限重试
- 没有任务幂等键
- 多实例定时任务并发执行
- 人工补单与自动补偿共用逻辑但没有去重

重点问题：
- 同一业务单是否可能被定时任务和人工入口同时补偿
- 失败重试是否存在上限和熔断

## 后台管理接口

高风险模式：
- 管理后台可直接退款、补款、解冻、调整费率
- 只有角色校验，没有审批链、金额上限、租户归属校验
- 审计日志不完整，无法追责和回放

高危判断：
- 只要低门槛后台入口能直接影响资产，优先按高风险分析

## 第三方回调

危险模式：
- 不验签
- 不校验来源 IP/商户身份
- 信任回调金额和状态
- 没有幂等
- 回调驱动本地状态任意跳转

必查点：
- 是否以本地订单、预期金额、商户配置为准重新校验
- 是否只允许从少数中间态迁移到成功态

## 典型高命中问题模板

### 模式 1：退款累计超额

信号：
- 代码只校验本次退款金额
- 没有校验历史已退款总额

后果：
- 多次退款累计超过实付

### 模式 2：余额并发透支

信号：
- 先查余额，再扣减余额
- 更新 SQL 不带余额约束

后果：
- 并发提现或并发扣减导致负余额

### 模式 3：重复消费导致重复出款

信号：
- MQ 消费失败重试
- 业务处理缺少去重记录和唯一索引

后果：
- 同一业务单重复落账、重复出款、重复发券

### 模式 4：后台越权补偿

信号：
- 后台接口可直接触发补偿
- 没有审批与金额限制

后果：
- 内部误操作或滥用直接造成资损
