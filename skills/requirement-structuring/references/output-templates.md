# 输出模板

## REQ/BR 需求清单（按模块分组，主模板）

**禁止**把所有 REQ/BR 平铺成 `### REQ-001 → #### BR-001 → #### BR-002` 的层级列表。这种格式可读性差，REQ 与 BR 的归属关系看不清。

**必须**按业务模块分组，每个模块一个 `###` 小节，每个小节内**一张统一的 REQ+BR 表格**，把 REQ 和它的 BR 放在同一张表里（REQ 行在顶，BR 行紧随其后，通过"类型"列区分）。

模块划分原则：
- 按**业务子域**分（如"编辑-零售通"、"编辑-售后工作台"、"展示全链路"、"主数据"）
- 按**能力**分（如"新增"、"修改"、"查询"）
- 一个模块包含 1 个主 REQ + 它的 BR，若 REQ 跨模块则在每个模块都列一次（表中注明"共享"）

**模板：**

```markdown
## 5. REQ/BR 需求清单（按模块分组）

### 5.1 模块一：<模块名>（如"编辑小数 - 零售通 PAD"）

父 REQ：**REQ-XXX** <REQ 描述>（优先级）— <一句话总结> [来源: <来源>]

| ID | 类型 | 描述 | 验收条件 | 来源 |
|---|---|---|---|---|
| REQ-XXX | REQ | <REQ 描述> | <REQ 验收> | <来源> |
| BR-XXX | BR | <BR 描述> | <BR 验收> | <来源> |
| BR-XXX | BR | <BR 描述> | <BR 验收> | <来源> |

### 5.2 模块二：<模块名>

父 REQ：**REQ-YYY**（若与模块一共享同一 REQ，标注"共享"）

| ID | 类型 | 描述 | 验收条件 | 来源 |
|---|---|---|---|---|
| BR-XXX | BR | <BR 描述> | <BR 验收> | <来源> |
```

## 图片资产清单（摘要 + 外链）

**禁止**把几十张 UI 截图大表格直接写进主报告。

**必须**在主报告用一段摘要 + 外链指向独立文件。核心状态机/流程图通过 §3 业务流程的 Mermaid 呈现，UI 截图索引挪到 `image_assets_<section>.md`。

**主报告模板（极简）：**

```markdown
## 4. 图片资产清单

本次 PRD 共引用 **<N> 张 UI 原型截图**，全部已下载归档。核心状态机/流程图由本次 Q01 根据文字描述 Mermaid 化（见 §3 业务流程）。

详细索引与抽查归属核对见 [`image_assets_<section>.md`](./image_assets_<section>.md)。
```

**独立文件 `image_assets_<section>.md` 模板：**

```markdown
# 图片资产清单 — <project_id> Q01（<section 说明>）

## 下载概况
- PRD 图片引用总数：<N>
```

**什么时候保留在主报告**：若只有 1-3 张**关键图**（状态机/流程图/架构图），可直接贴在主报告的 §3 业务流程或 §1 状态机章节，不用外链。**超过 5 张 UI 截图就必须外链**。

## 边界约定（Boundaries）

在报告末尾输出三级边界约定，供 Phase Q02/Q05a/Q06/Q07 引用：

```markdown
## 边界约定

### 必须做（Always）
- 所有金额计算使用 BigDecimal，精确到分
- 所有写操作必须有幂等保护
- ...（从 SE 中提取的强制约束）

### 需确认（Ask First）
- 是否需要支持批量操作（PRD 未明确）
- 退款是否需要审批流程（OPEN-003）
- ...（从 GAP/OPEN 中提取的待决策项）

### 禁止做（Never）
- 不在本次范围内的模块不改动
- 不引入新的外部依赖（除非技术方案明确要求）
- ...（从需求范围推导的排除项）
```

> **为什么需要边界约定**：下游 Phase 看不到 Phase Q01 的完整上下文，只看结构化产物。
> 边界约定让约束显式化，防止下游 Agent 各自猜测。

## 范围外发现（Noticed But Not Touching）

如果在结构化过程中发现了超出本次需求范围的问题，记录但不处理：

```markdown
## 范围外发现
- [代码] 现有订单表缺少 version 字段，无法支持乐观锁（与本次需求无关但影响并发安全）
- [需求] 相邻模块"结算"的状态机与本次"定损"有交互，但不在本次范围内
```
